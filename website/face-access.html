AAC Facial Recognition

See the person. Check the policy. Unlock the right door.

AAC Face Access is the planned AnyAiCam premium access module for entrance cameras. The AI Access Edge performs local face recognition, checks whether the enrolled person is authorized for that door and time, then requests an unlock through a supported access-control provider API. Standalone relay access is a separate local product path and is not the normal AAC Face Access appliance workflow.

Access-control integration

Connect to access-control platforms that expose a supported API

AnyAiCam does not need to replace the customer's access-control platform. Instead, a provider adapter can translate an approved AnyAiCam unlock decision into that vendor's documented unlock-door API call. Platforms such as Brivo, Avigilon and other enterprise systems would only be offered after the specific API/integration is validated; brand names here are examples, not a compatibility claim.

Customer connects the provider

An authorized administrator enters the provider/API credential in a protected AnyAiCam setup screen after purchase. The credential should never be embedded in public HTML, JavaScript or an activation code.

AnyAiCam maps doors

The administrator links a camera and an access-control door, for example Front Entrance Camera → Main Lobby Door.

Adapter performs the unlock

When policy passes, AnyAiCam calls the supported provider adapter with the minimum information required to unlock that specific door.

Camera → local face match → access policy → provider adapter → provider API → unlock door
Provider support is integration-specific: API authentication methods, door identifiers, rate limits, cloud/local availability and certification requirements differ by access-control company. AnyAiCam should publish a tested provider compatibility list before production sales.
Camera-card experience

The door belongs on the camera card

For an entrance camera linked to a door, the customer should not have to jump between unrelated screens. The camera card can surface door status and the actions the signed-in user is permitted to perform.

Unlock icon

A door-unlock icon appears on the camera card only when that camera has a configured door relationship and the signed-in user has manual-unlock permission.

Facial recognition state

The card can show whether Face Access is active, paused or unavailable for that entrance without exposing biometric details.

One audit trail

Manual unlocks and recognition-based unlocks should record who/what triggered the action, which door was requested, the provider response and the timestamp.

Enrollment and privacy

Recognition must be permissioned and fail secure

Consent-based enrollmentEnroll only people the customer is authorized to enroll, with clear retention and removal controls.
Encrypted templatesPrefer encrypted face embeddings/templates over using raw face photos as the normal matching record.
Liveness / anti-spoofingUse anti-spoofing controls appropriate to the deployment before granting automatic access.
Confidence thresholdA weak or ambiguous match must not unlock the door. It should remain locked and optionally request another verification method.
Fail-secure behaviorIf recognition, policy evaluation, network connectivity or the provider API fails, the access request fails closed rather than assuming access is allowed.
Least-privilege API credentialsUse a provider credential restricted to only the doors/actions required for the site, with rotation and revocation support.

Two access-control paths

Integrated AAC Face Access or separate standalone relay control

Do not mix the roles: the AI Access Edge is the integrated AAC Face Access appliance for supported provider APIs. The Numato three-channel relay is intended for standalone door/gate control and is not required by the AI Access Edge or either VMS Edge appliance.
Candidate hardware image — final AnyAiCam production appliance remains subject to validation.
Integrated Face Access

AnyAiCam AI Access Edge — AAC Face Access

The dedicated AAC appliance runs the local face-detection/matching pipeline and access-policy decision, then talks to a validated access-control provider API. Final supported recognition-camera count will be based on AnyAiCam production benchmarks.

Standalone relay candidate — a separate local access-control path, not the VMS/AI Edge appliance.
Standalone access only

Numato Lab 3 Channel Ethernet Relay Module

A candidate local interface for standalone access-control designs that need dry-contact door/gate trigger outputs. It is not the normal accessory for the AI Access Edge and does not require either VMS Edge appliance. A compatible reader/intercom/controller and appropriate access-control power/lock hardware remain part of the standalone design.

Door icon behavior: the 🔓 control appears only for a camera linked to a configured door and a user authorized to operate it. Face recognition uses the same door policy; a successful face match alone is never sufficient.
