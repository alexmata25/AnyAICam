# Direct Dell test data backup and restore plan

This plan covers only the future test-only root `%ProgramData%\AnyAiCam-Test\<run-id>`. It does not authorize or perform a backup of the retained production `%ProgramData%\AnyAiCam` tree.

Before a separately authorized installation, use an administrator-controlled destination that reports `VolumeStatus=FullyEncrypted`, `ProtectionStatus=On`, and `EncryptionPercentage=100` in `Get-BitLockerVolume`; alternatively use an owner-approved encrypted archive whose encryption and recovery procedure are independently verified. Keep recovery material separately under the owner's control. Do not place recovery material beside the backup. Stop only the isolated test service, then copy the test root with `robocopy <source> <backup> /E /COPYALL /DCOPY:DAT /B /R:0 /W:0`. Treat any exit code at least 8 as failure. Generate a sorted manifest covering relative path, file hashes, alternate data streams, timestamps, attributes, and full security descriptors. Restore into a new disposable test root using the same metadata-preserving flags and compare the full manifest before resuming. Never restore over production data.

The fixture script `Test-DirectTestBackupTooling.ps1` uses only a unique disposable NTFS directory beneath this acceptance folder. It verifies content copy/restore hashes and, when the current token supports backup mode, checks timestamps, ACL/owner/audit SDDL, and an alternate data stream across backup and restore. It also reports the fixture volume's BitLocker state. A missing `SeBackupPrivilege`/`SeRestorePrivilege`, unavailable SACL access, or unencrypted/unidentified volume is a blocked verification result, not permission to grant privileges or weaken the procedure. The encrypted destination, key custodian, and administrator identity remain owner-controlled decisions before any production ProgramData backup.
