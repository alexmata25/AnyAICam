### Blockers found by the first run, resolved in 1.2.3

| Blocker | Root cause | Fix |
|---|---|---|
| **Anonymous cameras** never started | `_provisioned_camera_stream()` (`app/main.py`) returned nothing unless a `camera_credentials` row existed, although provisioning accepts cameras without credentials. | No credential row = stream the URL as-is. A stored credential that cannot be decrypted still stops the camera (never becomes anonymous). |
| **RTSP port** (simulator on 8554) | Discovery recorded only whether 554 or 8554 answered; `verify_device()` always tested port 554 with the default Hikvision path. | Discovery records `rtsp_port`; verification uses the camera's own ONVIF stream URI (port and path, asked without credentials), else the discovered port. Records without port information keep 554. |
| **MAC-less binding** (layer-3 link, no ARP MAC) | Binding required a MAC; the camera stayed `camera_not_bound` although its ONVIF UUID is a stable identity. | Without a valid MAC, the camera binds by its stable `device_key` with the same collision and orphan rules; a camera with a MAC binds exactly as before. |

## Customer release notes (draft)

**AnyAiCam 1.2.3** — the current release for AnyAiCam Ryzen appliances and for your own PC running Ubuntu 24.04 (64-bit Intel or AMD).

- **Install updates when you choose.** New versions appear in Settings → System; only the account owner can start an install.
- **Every update is checked before it installs**, and if a new version doesn't start correctly your appliance goes back to the version it was running. Recordings, cameras and settings are kept.
- **Clearer update status** in Update history.
- **More cameras work out of the box:** cameras that don't need a password, cameras that stream on a port other than 554 (such as 8554), and cameras on a different network segment.
- **Signing out from a phone** now works reliably.

## Install on Ubuntu 24.04 (x86_64)

Requirements: Ubuntu 24.04 LTS 64-bit; 4+ CPU cores; 8 GB RAM (16 GB recommended); 100 GB free; wired network with
internet during install; TCP 8000 and UDP 8189 free; `sudo`; an AnyAiCam account with a VMS licence (included with every
appliance, or bought for your own PC in My subscription).

```bash
sha256sum anyaicam-appliance-installer-1.2.3-vms-9f59f11561d9.tar.gz   # must be 5729f5de...ce29e
mkdir -p ~/anyaicam-installer
tar -xzf anyaicam-appliance-installer-1.2.3-vms-9f59f11561d9.tar.gz -C ~/anyaicam-installer
cd ~/anyaicam-installer
sudo ./install.sh          # or: sudo ./install.sh --repair  (keeps recordings, cameras, settings, accounts)
sudo ./validate.sh
```

## Rollback

| Situation | Path |
|---|---|
| An update fails on an appliance | Automatic: the applier restores the previous code, image and identity and reports `rolled_back`. |
| Return an appliance to the previous release by hand | Supported: `sudo anyaicam-rollback` — restores code, image, build, version and the installed-release record; refuses a stale rollback point; waits for `/version` and `/health`. Needs the agent from the 1.2.3 installer. |
| Stop offering a published release | Re-publish the previous signed release (`publish_update_release.py`); appliances already on the newer release are not downgraded. |
| Cloud | Blue/green rollback container. |
